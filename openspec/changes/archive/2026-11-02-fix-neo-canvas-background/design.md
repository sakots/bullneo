# Design

## Context

動機は proposal.md を参照。`src/bullneo.ts` の背景色定数は `#f0e0d6`。現在は `image_bkcolor` の設定、`Neo.Painter.prototype` の描画・PNG合成処理の置換、`Neo.start(false)` 直後の `Neo.painter.backgroundColor` 設定を行っている。

上流 `funige/neo` のmasterは調査時点で1.8.12。`src/painter.js` はインスタンスの `backgroundColor` を `#ffffff` で初期化する。`src/container.js` の `Neo.start` はコンポーネント初期化を行う。既存パッチが1.8系の実インスタンスへ適用されるかは未確認であり、色定数だけで白背景が直るとは断定しない。

## Goals / Non-Goals

**Goals:** 初期表示・消去後の表示・添付PNGで背景色と描画の保持を実画素で保証する。

**Non-Goals:** パレット変更、外側UIの配色変更、配信元変更、NEO本体の改変、バージョン別互換レイヤーの追加。

## Decisions

- 背景色は単一の定数 `#f1e0d8` を使用する。パレット内の似た色は別のユーザー機能なので置換しない。
- 実装時は1.8.12の配布物で初期化後の実際のPainterと背景合成経路を確認し、既存の適用箇所を修正する。新しいAPIで背景色を設定できる場合はそれを優先し、不要になった旧パッチは残さない。
- 新規表示、消去、PNG反映についてピクセル値を検証するブラウザ回帰テストを先に用意する。ソース文字列やモックによる設定値の転送確認では代用しない。
- `bullneoTest/index.html` をHTTP(S)配信してNEO 1.8系を動かす。実掲示板への投稿は行わない。

## Risks / Trade-offs

- 既存の `updateDestCanvas` 全体の置換は上流APIの変更に弱い。実インスタンスへの適用と上流の描画経路を確認してから最小の修正を選ぶ。
- 最新コミット取得に依存したテストは再現性が低い。回帰テストでは検証したNEO 1.8系のコミットを固定する。
- ローカル確認では実際の板の通信制約を網羅しない。確認した環境と限界を分けて報告する。

## Implementation evidence

- 検証コミット: `funige/neo@e6af093d4d06d187208be68eb5eb6c6112a2520c` (1.8.12)。
- 実ブラウザで `Neo.Painter` が未公開であることを確認。従来のプロトタイプパッチは実行されず、表示・PNG出力の白指定が残っていた。初期化後の実Painterに既存の合成処理を適用する形へ変更し、旧パッチと適用済みフラグを削除した。
- 修正前の回帰テストでは初期背景・PNG背景・クリア後の2画素が白で失敗。修正後は背景と描画保持の6項目が成功した。
- `bullneoTest/background.test.html` で固定版の回帰テストを再実行可能。マウス描画と投稿フォームへのPNG反映も確認した。実掲示板への投稿は行っていない。
